# 设备说明书交付

接入或扩展完成后，生成或更新 `<project_path>/docs/manual.html`，把相对路径登记到 `manual`。让用户可以独立使用、排障，并把设备交给别人。

## 复用模板与已有文档

新文档使用 [manual-template.html](manual-template.html)。已有说明书优先局部更新，保留用户写过的内容。

1. 替换所有 `{{占位符}}`，按实际命令数增删表格行和小节；没有事实来源的内容不要补成“已支持”。
2. 型号、路径、说明等文本先做 HTML 转义；不要把未转义文本插入标签或脚本。主题色使用有效颜色值，`HERO_MODE` 只取模板支持的值。
3. 使用模板中的主题变量保持一致。只删除不适用的章节，同时删除其导航项，避免跳到不存在的锚点。
4. 每条 CLI 示例提供具体可用的参数值。按目标终端的规则给带空格路径加引号，不把 `{r}` 或 `{python}` 等占位符原样交给用户复制。

## 内容从哪里来

| 章节 | 依据 |
|---|---|
| 设备简介 | `description`、板型、模块及本次实际完成的功能 |
| 接线与供电 | 核实过的引脚、接线图、电压和电源要求 |
| 怎么开始 | 通电、连接、开始使用所需的最短步骤；使用用户实际安装的 Agent 名称 |
| 可以怎样说 | 每条已登记命令的 `desc`，配一两个自然语言示例 |
| CLI 用法 | `argv` 的真实参数边界，`args` 的类型、范围和默认值；公共参数说明与解析器一致 |
| 返回值与错误 | 实现中使用的错误码和[协议参考](protocol-template.md)；超时可能表示结果未知 |
| 常见问题 | 从[排障指南](troubleshooting.md)选择适用于此设备的现象、原因和操作 |
| 版本与验证 | 实际固件/工具链版本、日期、已测试内容及待确认的实物效果 |

没有实现的错误码或功能，不因为模板里有就当成设备已经支持。WiFi 密码、令牌等私密配置不进入说明书。

## 页面要求

- 正文离线可读。模板的装饰性 3D 使用 CDN，加载失败会保留 CSS 背景，不能阻塞内容。
- 中文正文和表格在手机上可读；宽表格和命令允许内部横向滚动，正文不要超出视口。
- 命令可复制，复制失败要给出真实提示；禁用 JavaScript 仍能阅读。
- 尊重减少动态效果设置。模板的亮暗主题和 CSS 变量一起维护，不用额外动画影响操作。

## 交付前验证

1. 检查没有未替换的占位符，内部导航指向真实章节，图片或文件路径存在。
2. 检查命令块复制出的文本不含按钮文字、终端 `$` 提示符或解释性注释；至少核对一条带参数的示例。
3. 查看桌面与窄屏效果；检查说明书列出的命令与最新注册表一致。
4. 更新 `manual` 后，用可用的文件预览或浏览器打开。没有预览能力时提供完整路径，不声称已经打开。

Windows PowerShell 可使用 `Start-Process -FilePath '完整路径'`，macOS 使用 `open '完整路径'`，Linux 使用 `xdg-open '完整路径'`。

最终告知说明书位置、两三个可以直接说的指令，以及已验证的范围。扩展功能时同时更新受影响的用法、参数、接线与版本信息。
