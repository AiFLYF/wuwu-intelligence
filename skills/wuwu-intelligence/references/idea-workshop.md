# 创意工坊：把手头模块变成可选方案

适用于用户有模块但没有确定目标的情况。先帮助用户选择，再进入[新设备接入](new-device-playbook.md)；讨论方案时不操作硬件。

## 只补齐影响方案的信息

优先使用当前环境可用的问答工具，没有就用简短列表。已知信息不重问，最多围绕以下四类内容收集：

| 信息 | 示例 |
|---|---|
| 手头材料 | 主控、传感器、灯带、屏幕、电源；有无已登记设备 |
| 使用场景 | 桌面、卧室、户外、教学、送礼 |
| 最想获得的效果 | 解决一个实际问题、增加趣味，或学习某种技术 |
| 投入约束 | 希望多久完成、是否愿意购买配件、是否需要完全离线 |

用户只是随便看看时，可基于已知材料直接提出初步方案，并标明需要核实的材料；不必先让用户填写整套问卷。

## 给出 2–3 个有区别的方案

从模块实际能力出发，考虑“输入 → 处理 → 输出”的组合。推荐方案优先使用已有材料和已登记的接口，至少有一个能尽快验证效果的小方案。

每个方案说明：

- **效果**：用户能看到、听到或使用什么。
- **已有材料与缺件**：哪些可以直接复用，是否还缺电源、驱动或结构件。
- **难度与耗时**：主要工作在哪里，给出有条件的估计。
- **依赖**：是否需要网络、云服务、额外软件或付费配件。
- **第一步**：最小可验证成果是什么，后续可怎样扩展。

例如用户已有 ESP32、温湿度模块和灯带，可以比较“温度颜色提示灯”“桌面环境提示屏（需要屏幕）”“定时显示环境状态的灯光装置”。传感器型号、供电和输出能力未核实时，不宣称这些组合已经兼容。

## 选定后继续

用户明确选定方案后，复用已有目标、主控、控制方式、预算等信息进入接入流程。先完成不依赖缺件的工作；需要采购或实物确认的部分列清楚，不将方案选择视为额外消费或无关外部操作的授权。

如果用户要求修改方案，先调整影响的部分，保留已经确定的条件，不重新开始整轮访谈。
