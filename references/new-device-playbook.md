# 新设备接入手册(六阶段)

用户说"我买了个XX模块/板子,帮我接上并控制"时,走这个流程。面向小白:每阶段结束用大白话汇报,关键决定先问再做。

## 阶段1:确认目标(必做)
用小白能懂的话确认:
- 这东西是干什么的?希望最终实现什么效果?(如"手机/电脑一句话让它动")
- 有没有商品链接/型号?没有就让用户拍芯片丝印照片
- 用户手头有什么:杜邦线?电源?焊好的排针?
- 查资料确认:供电电压/电流、通信方式(UART/I2C/SPI/单线/PWM)、电平(3.3V/5V)、有没有库

## 阶段2:接线方案
- 画 ASCII 接线图;标明电源来源(独立 vs 板载)和**共地**
- GPIO 选择规则(ESP32-S3):避开 strapping(0/3/45/46)、USB(19/20)、Flash/PSRAM(26~37);推荐 38~42/47/48
- 电流 >500mA 的外设必须独立供电;感性负载(电机/舵机)加续流二极管
- **先断电再接线**,接完让用户拍照核对一遍再上电

## 阶段3:固件开发
- 复用 protocol-template.md 骨架(TCP+JSON+非阻塞状态机)
- 新建项目目录 <name>/firmware/<name>/<name>.ino(Arduino要求同名文件夹)
- 顶部用户配置区:WIFI/PIN/端口等集中放置

## 阶段4:编译烧录
- 项目有 tools/build_upload.ps1 就跑脚本;否则按 README 引导 Arduino IDE 手动操作
- 烧录口先问用户或让用户拔插USB看设备管理器变化来确定;确定后可记录到 devices.json 的 hardware.flash_port_default
- 编译报错:先看第一段红色错误,常见=缺库/版本不符/选错板子
- 烧录失败:按住BOOT再点上传;查COM口;换USB线

## 阶段5:PC端封装
- <name>/pc/xxx_dev.py 通信库(标准库优先)+ xxx_cli.py 命令行
- 每个固件cmd一个方法/子命令;--ip 自动记忆;连接失败中文提示

## 阶段6:测试 + 登记(必做)
- 逐条指令实测(连通→基础控制→动画/高级功能→状态查询)
- 全部通过后,在 devices.json 登记新设备档案:name/aliases(含中文口语叫法)/project_path/control/hardware/quick_examples
- 告诉用户以后怎么说人话控制它
