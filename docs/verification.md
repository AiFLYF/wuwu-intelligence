# 软件与模拟通信验收报告

日期：2026-10-14。范围：本地工作区的 Skill 安装、数据管理、命令执行、TCP 模拟通信、Demo 和说明书。

**结论：软件闭环可以实际运行。** 从安装后的 Skill 发起命令，能通过真实 TCP 连接改变模拟设备状态，再通过独立查询确认结果。此结论不包含实体硬件、固件烧录、串口或 BLE 实机兼容性。

## 本轮实际发现并修复的问题

### Windows 输出编码阻断程序调用

原先 `list` 在 Windows 管道中按 GBK 输出，UTF-8 JSON 读取会抛出 `UnicodeDecodeError`。现在工具输出统一使用 UTF-8，并为 Python 设备 CLI 设置标准输出编码；通过 ASCII 环境和中文实际 TCP 数据往返测试。

### 重装会删除安装目录中的设备数据

用真实安装器重复安装后，旧位置的 `devices.json` 确实消失。默认位置已改为 `~/.wuwu-intelligence/devices.json`，另支持 `WUWU_DEVICES_FILE` 和 `--registry`。两种 Agent 安装副本共享独立档案，重复安装后的内容校验通过。

`migrate` 保留旧文件、不覆盖已有目标，并保持相对路径含义。已移走的备份可通过 `--base-dir` 指定原目录。旧用户首次升级前仍需备份原安装目录中的数据。

### 真实内容会撑破说明书窄屏布局

空白模板检查正常，填入长 Windows 路径后，390px 页面实际扩展到约 650px。现已约束步骤网格宽度并允许长文本换行；验收改为使用完整生成的说明书，覆盖 320px 和 390px，而非只检查占位符模板。

### 设备登记与并发更新已补齐

新增 `register`、`show`、`update` 和管理操作的 `--dry-run`。正常验收流程已改为使用这些公开入口，不再直接编辑整个设备数组。更新必须携带读取时的 revision；成功修改自动保留原始字节备份，再原子发布新文件。

并发测试中还复现了 Windows 原子替换偶发拒绝访问，现对短暂文件占用进行有上限的重试，每次提交前重新核对版本；永久失败保持原文件不变。只重试本地文件提交，不重复执行设备命令。

并发保证针对通过工具操作同一个普通本地文件的进程。外部编辑器、同步工具或网络文件系统不一定遵守文件锁。Linux 分支已纳入 CI 配置，本轮进程与文件句柄验证在 Windows 上执行。

## 如何复现

```bash
# 仅需 Python 3.10+，独立创建测试数据，不接触默认设备档案
python tools/check_workflow.py

# 使用一个已安装的副本验证
python tools/check_workflow.py --installed-skill /path/to/wuwu-intelligence
```

每次运行在 `.workbuddy/verification/workflow-*/` 保存逐步 `report.json`、服务端请求记录、日志和生成的说明书；最近一次摘要为 `.workbuddy/verification/latest-workflow.json`。

前端和说明书浏览器检查：

```bash
python -m pip install -r requirements-browser.txt
python -m playwright install chromium
python tools/check_demo.py
```

模拟服务与 CLI 源码见 [examples/simulated-led](../examples/simulated-led/README.md)。实际安装测试使用项目级隔离目录，没有替换用户正在使用的 Skill 或注册表。
