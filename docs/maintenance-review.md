# 项目检查与改进记录

检查范围：README、Skill 工作流、设备注册表、校验工具、静态 Demo 和交付模板。仓库尚未包含实体设备固件或经过实机验证的驱动；已有本机 TCP 模拟设备和完整的软件验收。

## 已发现的问题与本次修改

| 问题 | 影响 | 修改 |
|---|---|---|
| 安装示例直接复制注册表，且把 `.gitignore` 当作升级保护 | 用户重复安装或升级时可能丢失设备数据 | 初始化使用排他创建；默认档案迁至独立目录，提供不覆盖的迁移入口，并实际验证重复安装后的数据保留 |
| 控制、排障流程要求无条件重试 | 响应丢失时可能重复触发运动、投料等动作 | 按错误和命令幂等性判断，工具始终只执行一次，超时报告结果未知 |
| 只有自然语言命令模板，缺少可验证的执行入口 | 参数错误、别名歧义和跨平台转义依赖 Agent 临时处理 | 增加标准库注册表工具，提供校验、列表、计划和参数数组执行 |
| 校验器的简化 YAML 解析与完整解析行为不一致，且只扫描“有 SKILL.md”的目录 | 某些错误元数据或缺失入口可能被漏报 | 统一使用 PyYAML，拒绝重复字段，校验类型和资源引用，不跳过破损 Skill |
| 3D 模块处于 UI 启动依赖链，加载遮罩可持续 50 秒 | 慢网络或模块失败时难以阅读和安装 | 移除阻塞遮罩；基础 UI 与 2D 演示先可用，3D 动态加载，信号流按需加载 |
| 页面用“连接硬件”“LIVE”等描述浏览器动画 | 访客难以判断能力边界 | 明示浏览器模拟，展示有限示例指令、CLI 和协议消息 |
| 复制失败也显示成功；移动菜单和标签页键盘支持不完整 | 复制的命令不可用，键盘用户易失去焦点 | 核实复制结果，去掉终端提示符，补焦点管理和 Home/End，关闭菜单恢复焦点 |
| 减少动态效果仍持续渲染；说明书按物理像素比较尺寸导致高 DPR 下重复 resize | 静态场景也持续消耗资源 | 动画调度按可见性与偏好停止；模板 resize 改为事件驱动，增加后台暂停 |
| 协议文档关于默认参数、E_JSON、串口阻塞读取的规则不一致 | 新设备实现容易出现错误或卡顿 | 统一参数校验、超时语义、分帧与缓冲上限，避免盲目试探未知引脚 |
| 设备登记依赖直接改 JSON，多个会话可能覆盖较新内容 | 设备或命令丢失，旧编辑覆盖新配置 | 新增 register/show/update、版本校验、系统文件锁、原始备份和原子写入，并用真实并发进程验证 |
| Windows 原子替换偶发拒绝访问 | 并发或临时文件占用下保存失败 | 有时限地重试文件提交，每次核对版本；保持设备命令只执行一次 |
| 缺少回归检查 | 文案、模板和代码修改后容易复发 | 增加 Python、Node 和 Chromium 检查，配置 Windows/Linux CI |
| 接入和排障指南过度依赖单一灯板项目，缺少清晰的完成条件 | 已有项目可能被重复搭建，不同主控可能套用错误步骤 | 区分登记、扩展、全新接入；重写参考文档，补完成标准与跨文档链接，按具体板型排障 |

## 验证边界

2026-10-14 最新本地验证：58 项 Python 测试通过；此前的 6 项 Node 测试和 6 组 Chromium 检查通过。另外跑通 28 次命令调用组成的软件流程，包含正式登记、版本化更新与新命令执行。具体结果见[软件与模拟通信验收报告](verification.md)。

- Python 测试通过临时本地脚本验证参数传递与退出码，不使用真实设备。
- Node 测试覆盖示例指令解析、参数边界及灯阵采样；浏览器测试覆盖实际交互、窄屏、键盘、复制失败、禁用 JavaScript、模块失败/延迟、无 WebGL 与减少动态效果。
- 说明书模板另行验证复制内容、脚本错误及高 DPR 下不会每帧重复调整画布尺寸。
- CI 配置将在推送后由 GitHub Actions 执行；本地通过不等于远程流水线已执行。
- 仓库校验器与 Claude 插件清单校验通过。当前环境随 Skill Creator 提供的旧版快速校验器未包含标准支持的 `compatibility` 字段，会对此误报；保留该字段，以 Agent Skills 规范和仓库校验为准。
- 工作流与协议指南已经统一，但仍需用具体设备完成编译、烧录、通信及实物测试。

## 建议的后续重点

1. **提供可复现的首个硬件示例。** 将一个经过验证的灯板项目作为独立示例发布，包含板型、接线、固定依赖版本、固件、CLI 和实际输出。这样新用户可以从安装走到首次实机成功。
2. **扩展通信回归覆盖。** 现有本机 TCP 模拟已覆盖分帧、错误、离线和迟到响应。后续增加实体设备、串口或 BLE 驱动时，复用同等验收标准。
3. **积累真实接入记录。** 记录验证过的板型、模块、工具链版本与限制，将“通用工作流”和“已验证设备能力”分开展示。

本次优先完善现有 Skill 与静态 Demo。未来如果需要浏览器直接控制硬件，应另行设计本地服务、设备授权与连接协议，不能直接把演示页的模拟命令当成真实控制接口。
